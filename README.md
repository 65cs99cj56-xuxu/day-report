# XZY Day Report

基于真实 Codex 或 zcode 会话记录，生成可回查的日度或自定义区间工作复盘。报告聚焦两类内容：项目进度，以及有明确证据的个人 AI 学习与实践。

本仓库内容可作为 Codex Skill 使用。Skill 的完整执行规范见 [`SKILL.md`](SKILL.md)，示例格式见 [`examples.md`](examples.md)。

## 能做什么

- 汇总今天、昨天、最近 N 天或指定日期范围内的真实工作记录。
- 从会话中的用户消息、实际操作、文件变化、测试结果、提交记录和明确决策中提炼事实。
- 识别工作处于已讨论、已实现、已验证、进行中、阻塞或仅分析等状态，避免把计划写成成果。
- 将同一项目中需求、开发、联调和验证等相关会话合并成管理者易读的结果摘要。
- 识别前后会话间的承接关系，例如后续会话验证、修正或落地了之前的结论。
- 只在会话明确留下未解决事项时生成“待完成”；没有明确遗留事项时省略该部分。
- 附上会话核验信息，便于回查总结依据和实际读取范围。

Skill 不会把会话标题或摘要当成事实依据，也不会把启动服务、运行脚本、统计数量等日报执行过程写成用户当天的工作成果。

## 会话来源

Skill 根据运行环境选择一种主要来源，避免重复统计同一会话：

1. **Codex 本机 JSONL（优先）**：读取 Codex Home 下的 `sessions/` 和 `archived_sessions/`。清单脚本为 [`scripts/inventory_codex_sessions.py`](scripts/inventory_codex_sessions.py)，使用 `python3` 运行。
2. **Codex App 会话工具**：本机 JSONL 不可读时，使用会话列表与分页读取工具，并确认候选列表没有因数量上限而不完整。
3. **zcode JSONL**：在非 Codex 环境中，根据系统提供的 auto memory 绝对路径定位会话目录；没有该路径时停止并说明原因，不会猜测目录。

读取会话的目标是完整核验指定时间范围内的工作，并不意味着把所有内容都写进日报。默认只将用户主任务视为独立会话，subagent、审批和其他内部派生会话不单独计数，其成果归入父任务。

## 默认行为

| 项目 | 默认规则 |
| --- | --- |
| 日期范围 | 用户未说明时，先询问要总结今天、昨天、最近 N 天还是自定义日期范围 |
| 时区 | 使用本地时区，并在回报中说明 |
| 统计范围 | 默认 `cwd`，即当前项目；完成时说明实际范围 |
| 全部会话 | 用户明确说“所有会话”“全部任务”或“今天所有 Codex 会话”时使用 `all`，不按项目目录过滤 |
| 子代理 | 默认不单独纳入；只有用户明确要求时才单独复盘 |
| 输出形式 | 直接在对话中回复；自动化运行时写入本次 Issue 动态，不生成或上传日报文件 |
| 内容边界 | 只写项目进度和有证据的 AI 成长；不以测试数量、服务启动或日报操作凑条目 |

`cwd` 范围按会话元数据中的项目工作目录过滤，不表示读取或写入报告文件的位置。若需要跨项目汇总，请明确要求 `all`。

## 调用时应提供的指令

只写“总结一下”通常不足以确定统计范围。建议在调用 Skill 时同时告诉智能体以下信息：

1. **时间范围**：说明今天、昨天、最近 N 天，或明确的起止日期。自定义区间建议写成闭区间，例如 `2026-10-01 至 2026-10-09`。
2. **会话范围**：说明只看当前项目（`cwd`）还是覆盖全部项目会话（`all`）。如果省略，Skill 默认只看当前项目。
3. **特殊纳入项**：如果要单独汇报 subagent 或其他内部派生会话，需要明确提出；否则默认排除。
4. **额外输出要求**：如需不同于默认的语言、格式、读者或篇幅，应明确说明。默认直接输出精简的“我的今日进度”，并附会话核验信息。
5. **访问前提**：智能体需要能读取对应会话来源。Codex 本机模式需要访问真实 Codex Home；zcode 模式需要系统提供 auto memory 路径。权限不足或会话源不完整时，应如实说明，不能用当前对话记忆代替。

### 可直接使用的提示模板

```text
使用 $xzy-day-report 总结【今天 / 昨天 / 最近 N 天 / YYYY-MM-DD 至 YYYY-MM-DD】的工作。
统计范围：【当前项目 / 所有会话】。
【可选】单独纳入 subagent 会话。
请按 Skill 的证据和输出规则直接给出日报；如果会话范围不完整或无法读取，请说明，不要推测或补造。
```

例如：

```text
使用 $xzy-day-report 总结今天所有 Codex 会话，按本地时区统计。请合并跨项目的重复事项，附会话核验信息；不要生成文件。
```

```text
使用 $xzy-day-report 总结 2026-10-01 至 2026-10-09 的当前项目工作。只依据该区间内的会话证据，按默认格式输出，并列出明确尚未完成的事项。
```

## 智能体执行要求

调用时不必重复粘贴 `SKILL.md` 的全部规则；加载本 Skill 后，至少确保智能体得到并遵守以下指令：

- 先确认时间窗口和统计范围；缺少时间范围时询问，缺少统计范围时按当前项目处理并在结果中说明。
- 在开始读取时固定本次窗口的排他截止时间。对于包含今天的窗口，截止时间是实际开始读取时的当前时间；分页和后续读取必须复用同一截止时间。历史日期的截止时间为结束日次日 00:00。
- 仅使用指定窗口内的用户主会话事实；摘要、标题、上下文记忆、粘贴材料、未来计划和窗口外历史不能单独作为当日证据。
- 将完整会话读取或分页到结束，不因内容多而跳过、抽样或静默截断；0 个符合条件的会话时停止并询问是否扩大范围。
- 每条结论都要有可回查证据，并区分讨论、实现、验证、进行中、阻塞和分析状态。不要将建议或尝试写成已完成。
- 日报正文只包含有明确结果的项目进度和 AI 学习/实践。没有 AI 学习证据时，明确说明未发现，不得编造；只有明确遗留事项才输出“待完成”。
- 默认不将日报 Agent 自己的扫描、读取、汇总和发布过程写入进度，也不把普通开发行为包装成 AI 成长。
- 完成后说明来源模式、时间窗口、时区、统计范围、读取的主会话数量及核验信息；无法完整读取时应明确报告限制。

自动化任务另需使用触发记录中的实际运行时间来固定截止时间；不能按计划运行时间声称读取了尚未发生的工作。

## 默认日报格式

```text
我的今日进度：

1. 完成/解决/明确 + 项目结果。
2. 完成/解决/明确 + 项目结果。
3. 形成/掌握/完成 + 有证据的 AI 学习或实践。

待完成：
明确尚未解决或仍在进行的事项。

会话核验：
- 会话 ID、时间、项目目录等可回查信息

来源与核验：
来源模式、时间窗口、时区、统计范围和读取情况。
```

通常采用 4 至 6 条，每条一句话、只表达一个主要结果，优先描述解决的问题或形成的结果。事项较少时按证据实际数量输出，不补凑条目。没有明确遗留事项时，省略“待完成”部分。

普通对话中，完整总结直接放在回复正文；自动化运行中，完整总结放在本次 Issue 动态区的智能体最终回复中。默认不生成 Markdown 日报文件，也不上传或附加会话材料。

## 隐私与核验

会话可能包含项目代码、内部讨论或个人信息。只读取完成用户指定总结所需的会话，不要将原始会话全文放入日报或上传到其他位置。报告中的结论应可回查；会话读取权限、工具分页或数据来源不完整时，应先披露限制，而不是猜测。
